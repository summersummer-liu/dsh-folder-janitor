# 给一个 38 GB 的学习文件夹做断舍离

一次真实的文件夹整理，连同用的插件一起开源。

- `docs/` — 9 页竖版图文（PDF + 1080×1440 PNG），可以直接发小红书
- `plugin/` — 干活的插件 `dsh-folder-janitor`：只读体检 → 可复核的清单 → 带日志执行 → 一键撤销
- `record/` — 整理前后的真实数据、时间线、数字汇总（`before-after.md`、`timeline.md`、`summary.json`）
- `review/` — 独立审核员的验证记录
- `xhs/` — 小红书文案方案

## 这次整理的对象

`D:\阅读学习`，一个建筑与设计方向的学习资料目录：53,481 个文件、38.63 GB、19 个顶层项。

真正乱的地方只有三处：一个文件夹装了 92% 的文件；两个 400MB 级散件躺在根目录；三个文件夹的名字是下载工具生成的（`attachment_17434050909562708`、45 个字的长名、`中体量建筑_副本`）。还有一个隐藏的 `.pdftmp`，503 个文件、71.9 MB。

## 做了什么

6 条计划，7 次成功移动，0 个文件丢失：

- `.pdftmp` → `_trash/2026-10-25/`（不删，只收起来）
- 《WKW》.pdf、原画集.zip → `_待归类/`
- 三个乱名目录改成能读的名字
- 根目录新增 `README.md` 目录索引

13 个项目文件夹一个字节没动。

唯一失手的一条：45 字符的长名目录原地改名被系统拒绝（`EPERM`）。它的 DACL 里确实有一条下载工具留下的拒绝项，但受控试验证明那条不拦改名，也查不到占用进程 —— 原因没查清。最后改成「先横着挪进 `_待归类`，再挪回根目录」两步完成，两步都进了日志。

## 数字怎么核

`record/summary.json` 是全套数字的唯一来源，`record/timeline.md` 记录每一刻在干什么。审核员独立复算过：搬运前后内容哈希多重集一致，被搬的 1,789 个文件全部对得上，`.pdftmp` 的 503 个文件在 `_trash` 里齐全。

## 插件

`plugin/` 是 `dsh-folder-janitor` v0.2.0 的源码。四个工具：

| 工具 | 干什么 |
|---|---|
| `folder_inventory` | 只读体检：类型、体积、重复、垃圾，给出策略建议 |
| `folder_plan` | 出清单，不动文件。支持按类型/月份/项目词聚类的自动策略，也支持逐条列出的 manual 清单 |
| `folder_apply` | 按清单执行，边搬边记账，搬完回盘核对落点 |
| `folder_undo` | 日志倒着走，只回滚还完好的文件 |

设计上刻意不做的事：不删文件（只进 `_trash`）、不覆盖同名文件、不改项目文件夹、不碰 `plugins/`、`.git`、`node_modules` 这类目录。撤销要过三道检查：目录身份、目标还是不是普通文件、内容有没有被动过。

### 装到你自己的 DSH 上

前提是装了 DSH（DeepSeek Harness）`>= 0.2.1-rc.2`。这不是独立软件。

**一条地址（推荐）**

打开 DSH → 设置 → 插件 → 添加插件，粘这一行：

```
https://github.com/summersummer-liu/dsh-folder-janitor
```

点安装。装完四个工具就出现在工具列表里。

如果之前装过别的版本，先在插件列表里把它卸载，再粘地址——包结构变过的话，旧行会缓存旧路径，直接覆盖会报「failed to import」。装完没出现工具，就把 `include:dsh-folder-janitor` 关掉再开。

**用发布包（网络不好时）**

1. 下载 [`dist/dsh-folder-janitor-0.2.0.zip`](dist/dsh-folder-janitor-0.2.0.zip)，解压到任意目录，比如 `D:\tools\dsh-folder-janitor`。
2. 回到添加插件那个框，粘解压后的目录路径（只写路径，别写别的）。
3. 同样：工具没出现就关掉插件行再开。

验证：随便找个文件夹说「先看看这里都有什么」，能返回体检报告就是通了。卸载在设置 → 插件里关掉那一行。

Windows 实测过；macOS / Linux 能跑但边界分支（撤销、改名）没验过。许可证 MIT，见 [`LICENSE`](LICENSE)。

跑测试：`cd plugin && node test/run.mjs && node test/edge.mjs && node test/manual.mjs`（29 + 23 + 15 项）。`plugin/test/adversarial.mjs` 是另一套 140 项的对抗测试。

## 已知局限

- `by-project` 不做中文分词，靠共词聚类，文件名起得随便的目录会聚不上
- 目录名太长时会改名失败（EPERM）。这次的原因没查清：ACL 里那条 deny 经受控试验证明不拦改名，也查不到占用进程，最后靠两步挪动绕过
- 体检有 20,000 文件的扫描上限：这个目录 5.3 万个文件，`folder_inventory` 会截断并标 `truncated`，真实的类型分布是拿独立脚本复算的
- 257 个 macOS 元数据文件 `._*`（合计 1 MB）还在原地，没清
- 插件没有打包上架，路径写死在本机，不保证开箱即用
