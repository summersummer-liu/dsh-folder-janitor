## 二、正文（817 字，含标点和空格）

先说清楚：这不是双击就能打开的软件，得装在 DSH（DeepSeek Harness）里。没装 DSH，下载了也跑不起来。

如果你电脑里有个不敢打开的文件夹——素材、截图、下载、改到第三版的作品集全堆在一层——这个插件是给你写的。

它只有四个动作，每步都能停下来看。

体检：只看不动。告诉你里面有多少文件、分别是什么类型、哪些是重复的、哪些是空文件和草稿。

清单：列一张「哪个文件搬到哪」的表。你先看，不满意就重算。没有清单，它不动手。

执行：只搬清单上写了的。搬一条记一笔账，搬完回头核对，真落在新位置才算数。撞名的不覆盖，不会悄悄盖掉。

撤销：账本倒着走，文件退回原位。

它不删东西。草稿和临时件进 _trash，重复件进 _duplicates，原路留着，能捞回来。

这四步不是流程洁癖。以前我一句命令直接搬，半小时后就想不起某个文件原来在哪；有一次连项目的说明文件都被一起扫走了，才回头改成现在这样。

207 项自动测试是我拿它往墙上撞撞出来的：主流程 29、抗打击 23、手动清单 15、独立对抗 140。其中 8 个是真问题，最狠的一条是「撤销只比文件大小」，内容被改过也照样退回。现在撤销前会看位置、大小、修改时间，小文件再多比一次内容。

真搬过一次：53,481 个文件、38.63 GiB，7 次移动，0 个文件丢失，每个落点都读回来核对过。

三个局限，说在前面：只在 Windows 上实测，macOS 和 Linux 没验。没上架任何插件市场，要手动解压安装，不写代码的人大概率卡在这一步。撤销对「整个文件夹」不检查里面内容——文件夹被搬走以后，里面文件被改过，它照样整体挪回去。

装法：解压发布包（40KB），在 DSH 里说「把这个目录装成插件：你的解压路径」，工具没出现就把插件那一行关掉再打开。DSH 版本不低于 0.2.1-rc.2，MIT 协议。

没装 DSH、或者只想要「一键变干净」的，别装。它不猜，它要你先看清单。

发布包在 GitHub 的 Release 里：github.com/summersummer-liu/dsh-folder-janitor

## 七、不能写的（边界）

1. 不承诺下载地址。已有公开地址：GitHub Release v0.2.0（github.com/summersummer-liu/dsh-folder-janitor/releases/tag/v0.2.0），仓库 dist/ 里也有 zip。有人问"哪里下"就给这个地址，别私信发文件。
2. 不说"全自动""一键清空"。它要先出清单、要你确认，这是它的设计，不是缺点。
3. 不说支持 mac 和 Linux。只在 Windows 上实测过，别的系统能跑不等于验过。
4. 不把"8 个真问题"包装成"零 bug"。207 项测试是撞出来的，不是证明它没毛病。
5. 不说"绝对不会丢文件"。文件夹级的撤销没有内容护栏，这条已经写在第 7 张里了。
6. 截图打码。目录里可能有客户图纸、报价、甲方名字。
7. 不写具体路径，也别露文件夹真名。截图把地址栏盖掉，读者不需要知道我的盘长什么样。
